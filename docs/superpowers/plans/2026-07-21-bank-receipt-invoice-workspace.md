# 发票及银行回单识别入账与财务工作台实施计划

> 本文件只定义实施范围、数据生命周期、接口和验收标准。本阶段不修改业务代码。

## 目标

在现有电子发票导入能力的基础上，增加银行回单调用 MinerU 识别后人工选择合同入账的能力，并将发票、回单统一到“发票及回单”工作台。同时补齐已挂账/已入账的清除流程、失败文件删除流程、单据多合同拆分，以及零星用工详情页。

## 已确认的业务规则

- 发票和银行回单都必须先识别、复核、分摊，再由人工确认正式挂账/入账。
- 一张发票或一张银行回单可以拆分到多个合同。
- 收款只能选择上游合同。
- 付款可以选择下游合同和管理合同，允许同一张付款回单混合分摊到两类合同。
- 最终确认时，有效分摊金额合计必须等于源单据金额，精确到 0.01 元。
- 候选合同支持按合同名称片段远程模糊查询，返回合同全名；推荐合同和人工查询结果都保留。
- “删除”只用于上传/识别/挂账/入账失败且尚未生成正式记录的文件。
- 已挂账发票使用“清除挂账”，已入账回单使用“清除入账”。清除是可审计的撤销，不是无痕物理删除。
- 已成功识别但不准备处理的文件使用“忽略/作废”，不能用删除代替。
- 清除默认按整张源单据原子执行，撤销该单据产生的全部正式记录；清除后可以重新分摊和确认。
- 原始 PDF、XML/OFD、MinerU 原始结果、识别结果和清除历史必须保留。
- 上传、识别、确认、清除、删除都必须受权限控制并记录审计日志。

## 现有基础与边界

- 发票导入已有批次、明细、分摊、候选和确认工作台，可复用其异步处理和人工确认模式。
- 系统配置使用 `sys_config` 键值表，前端入口为 `SystemSettings.vue`。
- 零星用工当前只有列表/弹窗编辑，正式模型为 `ZeroHourLabor` 及 `ZeroHourLaborMaterial`。
- 上游已有收款表，下游和管理合同已有付款表；需要增加源单据追溯字段，避免重复入账。
- 现有正式收付款表使用日期字段，银行回单应额外保存完整交易时间。
- 第一阶段不自动计入无合同费用；是否允许进项发票分摊到管理合同按本计划支持。
- 零星用工的应付款、挂账、付款是独立财务明细，不是把人工、车辆、材料构成金额重复展示。
- 第一阶段发票/回单候选目标仍限定为上游、下游和管理合同；零星用工财务明细先支持详情页手工维护，并预留以后接入识别入账的来源字段。

## 数据生命周期

统一适用于发票导入项和银行回单导入项：

```text
uploaded -> processing -> needs_review -> ready -> confirmed -> cleared
                                      \-> failed
                                      \-> ignored
```

- `failed`：允许重试和删除。
- `needs_review`/`ready`：允许修改识别结果、添加/修改分摊、确认或忽略。
- `confirmed`：只能查看正式记录或执行清除。
- `cleared`：保留源文件和审计快照，可重新分摊并生成新版本正式记录。
- `processing`：禁止删除、清除和确认，避免后台任务与人工操作竞争。
- 同一源单据使用流水号/发票号码或文件哈希去重；已清除记录应提示打开原记录，不应生成无关联的新记录。

## 计划任务

### 任务 1：统一导入数据模型与迁移

**范围：** 新增/调整银行回单导入表；扩展发票导入表状态、删除和清除字段；增加源单据到正式记录的追溯字段。

**建议模型：**

- `bank_receipt_batches`：批次、原始文件、处理统计、上传人和状态。
- `bank_receipt_items`：PDF、哈希、方向、交易时间、金额、币种、付款/收款方、账号、摘要、核心流水号、MinerU 原文、标准化结果、置信度和状态。
- `bank_receipt_allocations`：上游/下游/管理合同目标、分摊金额、状态、确认人和正式记录 ID。
- `bank_receipt_match_candidates`：候选合同、评分和匹配依据。
- `finance_zero_hour_payables`：零星用工应付款类别、金额、预计日期、说明和附件。
- `finance_zero_hour_invoices`：零星用工挂账日期、发票号码、金额、税额、供应商和附件。
- `finance_zero_hour_payments`：零星用工付款日期、金额、收款方、账号、银行、付款方式和凭证。

**正式表追溯字段：**

- 上游收款、下游付款、管理付款增加 `source_bank_receipt_item_id`、`source_bank_receipt_allocation_id`、`bank_serial_number`、`transaction_at`。
- 上游/下游/管理正式发票表增加对应的 `source_import_item_id`、`source_import_allocation_id` 清除所需约束和状态关联。
- 对流水号、导入分摊来源建立唯一索引，阻止重复正式记录。

**验收：** migration 可在空库和已有数据上升级；源单据、分摊、正式记录之间可双向追溯；删除源文件不会级联删除已确认正式记录。

### 任务 2：系统配置增加 MinerU API

**后端：**

- 在 `SystemConfigUpdate`、系统配置读写接口中增加 `mineru_api_url`、`mineru_api_key`、`mineru_enabled`、`mineru_timeout_seconds` 等字段。
- API Key 必须加密后写入数据库，解密密钥由独立环境变量提供；接口只返回脱敏值，日志和错误信息不能泄露完整密钥。
- 仅管理员可读取/修改敏感配置；非管理员只获得是否已配置和脱敏状态。
- 增加“测试连接”接口，返回连接成功、鉴权失败、超时或服务不可用等明确结果。
- 识别服务不得允许用户提交任意 URL，避免 SSRF；实际调用地址只能来自受控配置。

**前端：**

- 在系统管理的“系统配置”页增加 MinerU 配置区：启用开关、API 地址、API Key、超时、测试连接、保存配置。
- API Key 默认掩码显示，编辑时不回填完整密钥。
- 保存后显示“已配置/未配置”，不显示密钥原文。

**验收：** 配置重启后仍有效；无配置时回单导入显示可理解的配置缺失；测试连接结果可区分 401、超时和服务端错误。

### 任务 3：银行回单识别与人工入账服务

**识别链路：**

1. 上传 PDF，校验类型、大小、页数并计算 SHA-256。
2. 保存到 MinIO/上传目录，创建批次和明细。
3. 优先提取 PDF 文本层；文本缺失或版式异常时调用 MinerU。
4. 按 `交易日期`、付款人、收款人、账号、`币种及金额`、摘要、`核心流水号` 解析。
5. 中文金额与 CNY 数字金额双重校验，不一致时进入人工复核。
6. 根据本公司银行账户配置判断 `receipt`、`payment` 或 `unknown`，不能根据摘要中的“付”字单独判断。
7. 生成候选合同，但不自动确认。

**候选合同搜索：**

- 提供统一远程搜索接口，按方向过滤合同类型。
- 合同名称使用安全的包含匹配，支持输入部分合同名称匹配完整合同名。
- 结果显示合同类型、序号、编号、全名、对方单位和剩余可收/付款金额。
- 精确匹配、前缀匹配、包含匹配依次排序；必要时增加 PostgreSQL `pg_trgm` 索引。
- 前端搜索框使用 300ms 防抖、最多 20 条、保留已选项并合并系统推荐项。

**正式入账：**

- 收款写入上游收款表，付款写入下游付款表或管理付款表。
- 一张回单可生成多条正式记录，但全部记录金额合计必须等于回单金额。
- 使用数据库事务和行锁，防止并发确认、重复确认和部分写入。
- 保留原始 PDF 链接、摘要、交易时间、流水号和来源分摊 ID。

**接口建议：**

- `POST /api/v1/bank-receipts/batches`
- `GET /api/v1/bank-receipts/batches`
- `GET /api/v1/bank-receipts/batches/{id}/items`
- `GET /api/v1/bank-receipts/contracts/search`
- `POST/PUT /api/v1/bank-receipts/items/{id}/allocations`
- `POST /api/v1/bank-receipts/items/{id}/confirm`
- `POST /api/v1/bank-receipts/items/{id}/clear`
- `DELETE /api/v1/bank-receipts/items/{id}`（仅失败且未生成正式记录）

### 任务 4：发票导入补齐清除、删除与拆分规则

- 发票确认时有效分摊合计必须等于发票价税合计；不能只校验“不超过”。
- 增加“清除挂账”接口，按源发票原子撤销其全部正式发票记录。
- 增加清除原因、清除人、清除时间、清除前金额和正式记录快照。
- 增加“删除失败文件”接口；后端再次校验状态，不能仅依赖前端按钮隐藏。
- 对已识别但未处理的正常文件提供“忽略/作废”，要求填写原因。
- 清除后允许原单据重新编辑分摊并生成新版本，旧正式记录保持可审计状态。

### 任务 5：统一“发票及回单”工作台与导航

- 将左侧“电子发票”入口改为“发票及回单”。
- 保留同一页面的两个标签：`发票识别入账`、`回单识别入账`。
- 发票标签复用现有发票批次/明细/分摊界面，补充删除失败文件、忽略、清除挂账和金额完整校验。
- 回单标签提供 PDF 上传、识别结果、原始 PDF 预览、收付款方向、对方单位、交易时间、金额、流水号、候选合同、拆分分摊和清除入账。
- 两个标签共用状态筛选、批次查看、失败重试、审计历史和远程合同搜索交互。
- 标签页保持工作台式密度：单据列表用于扫描，抽屉/详情面板用于复核，危险操作放在明确的二次确认中。
- 移动端至少保证上传、查看、合同选择和确认按钮不溢出；清除与删除不得用相同颜色或相同文案。

### 任务 6：零星用工详情页

**路由：** 新增 `expenses/zero-hour-labor/:id`，列表行点击或“查看详情”进入详情页。

**页面区域：**

- 基本信息：用工日期、归属、派工单位、关联上游合同、说明、审批状态、审批文件。
- 成本构成：单独展示现有人工、用车、材料的数量、单价、税率和合计，作为基本业务数据。
- 应付款明细：支持多条新增、编辑和删除，字段包括类别、金额、预计日期、说明和审批附件。
- 挂账明细：支持多条新增、编辑和删除，展示发票号码、日期、金额、税额、供应商、来源文件和状态。
- 付款明细：支持多条新增、编辑和删除，展示付款日期、金额、收款方、账号、银行、付款方式、凭证文件和状态。
- 金额摘要：应付、已挂账、已付款、未付款，使用与合同详情页相同的金额口径。

**后端：**

- 新增零星用工详情响应，使用受控数量的预加载查询加载材料、上游合同、应付款、挂账和付款关联数据，避免 N+1 查询。
- 创建零星用工应付款、挂账、付款三类子表、Schema、Service 和 CRUD 接口，外键指向 `zero_hour_labor.id`。
- 为零星用工挂账、付款预留可空的发票/回单导入来源字段；本期手工维护时保持为空。
- 删除零星用工主记录前检查财务子表；存在挂账或付款时禁止直接删除，必须先按财务撤销规则处理。
- 增加查看详情、查看文件和必要的更新/删除权限校验。

**前端：**

- 复用上游/下游合同详情页的分区、金额摘要和明细表格模式。
- 列表保留快速编辑，但新增“查看详情”，避免把所有财务信息塞进弹窗。
- 在移动端改为纵向信息区块和可折叠明细。

### 任务 7：权限、审计、删除与清除安全控制

- 新增或复用上传、识别、确认、删除失败文件、清除挂账、清除入账、配置 MinerU 的权限。
- 所有清除操作保存原因、操作人、时间、源单据、正式记录 ID、金额和分摊快照。
- 清除接口使用事务、行锁和幂等检查；已清除单据重复调用返回当前状态而不是再次删除。
- 删除接口在服务端拒绝非 `failed` 状态、已生成正式记录或正在处理的文件。
- 原始文件删除失败时保留数据库失败状态并提供重试，不产生“数据库已删但文件仍在”或反向不一致的误导提示。

### 任务 8：测试、迁移和文档

**后端测试：**

- MinerU 配置读写、脱敏和权限。
- 银行回单文本解析、金额双校验、方向判断和核心流水号去重。
- 收款拆分到多个上游合同。
- 付款拆分到多个下游/管理合同以及混合分摊。
- 发票拆分金额必须等于价税合计。
- 确认、清除、重新确认的事务和幂等行为。
- 失败文件可删除，正常或已确认文件删除被拒绝。
- 候选合同部分名称查询、方向过滤、合同全名返回和无结果场景。
- 零星用工详情一次加载及权限。
- 零星用工三类财务明细 CRUD、金额汇总、主记录删除保护和文件权限。

**前端测试：**

- 左侧导航显示“发票及回单”。
- 两个标签正确切换且各自保留筛选/批次状态。
- 候选合同远程模糊搜索、防抖、推荐项合并和已选项保留。
- 分摊金额不足/超额时禁止确认。
- 删除、忽略、清除按钮按状态显示并触发不同确认文案。
- 零星用工详情页基本信息、应付款、挂账、付款四个区域正确渲染。

**文档：**

- 更新 API 文档、用户操作手册、部署环境变量和数据库迁移说明。
- 增加 MinerU 配置、回单上传、人工合同选择、拆分、清除和失败删除的操作说明。
- 用提供的 4 张中信银行回单作为回归样本，另增加扫描件、重复件、金额不一致和失败重试样本。

## 完成标准

- 系统配置页面可以安全保存并测试 MinerU API。
- 左侧入口显示“发票及回单”，发票和回单分别位于两个标签页。
- 回单能够识别收/付款方向、对方单位、交易时间、金额和流水号。
- 发票和回单均支持部分合同名称模糊查询、候选合同推荐和多合同拆分。
- 确认前不写入正式挂账/收付款表；确认后可追溯到源文件和分摊。
- 已确认记录只能通过清除流程撤销，失败文件才允许删除。
- 清除后可重新分摊和重新入账，历史版本和审计记录完整。
- 零星用工详情页包含基本信息、应付款明细、挂账明细和付款明细。
- 迁移、后端测试、前端测试和文档全部通过。

## 推荐实施顺序

1. 先完成数据库模型、迁移、状态机、权限和审计基础，冻结正式记录追溯方案。
2. 完成 MinerU 系统配置和连接测试，再实现识别适配器。
3. 实现银行回单解析、去重、候选查询和多合同分摊服务。
4. 补齐现有发票的等额分摊、失败删除、忽略和清除挂账。
5. 实现发票及回单统一入口和两个标签页，并完成端到端测试。
6. 创建零星用工财务子表和接口，再实现详情页及列表跳转。
7. 最后执行全量回归、升级演练、权限核对和文档更新。
